# ReserveUrTime — Canonical Memory after Phase 4

- Project name: ReserveUrTime.
- `frontend/` and `backend/` are independent npm applications and start in separate terminals.
- Backend architecture: Models / Controllers / Routes / Services; React is the frontend View/client.
- Roles: Customer, Platform Admin (`platform_admin`), Restaurant Admin (`restaurant_admin`).
- Platform Admin owns homepage/platform presentation, Restaurant public listing records, Restaurant Admin account lifecycle and listing-change approvals.
- Platform Admin has no Restaurant-internal Menu/Table/Reservation/Gallery CRUD API.
- Restaurant Admin is backend-scoped to exactly one `restaurantId` through the authenticated user.
- Restaurant Admin owns internal `RestaurantProfile`.
- Public Restaurant name/listing image remain Platform-owned and require `ListingChangeRequest` approval.
- Phase 4 Restaurant Admin operations are implemented:
  - Menu Category CRUD/soft removal/restore;
  - basic Dish CRUD/soft removal/restore;
  - dish ingredients, price, image, order and availability;
  - Dining Table CRUD/status with protection for upcoming active reservations;
  - Restaurant reservation schedule/status management;
  - internal Gallery CRUD/soft removal/restore.
- Restaurant-owned operational writes force `restaurantId = req.managedRestaurantId` server-side.
- Phase 4 intentionally has no GLB/GLTF/modelUrl/exploded-layer fields yet.
- Galaxy Restaurant Search remains platform Restaurant-name/Cuisine search.
- Next phase: Phase 5 Public Restaurant Experience + Basic Menu/Search/Filter.
- Real GLB/GLTF 3D + exploded/layered assembly remain Phase 6/7.
